# 硬件加速

> 状态：稳定（可选，默认关闭）
> 适用版本：OmniMorph 1.0.0-alpha.4.1

OmniMorph 提供可选的客户端硬件加速，用于降低模型渲染的 CPU 开销。它默认关闭；不可用时自动回退 Java 路径。

## 加速方式

| 模式 | 说明 |
| --- | --- |
| **自动** | 优先 GPU 绘制与可用的 SIMD 准备；GPU 失败时回退完整 Java 路径 |
| **仅 SIMD** | 使用原生 CPU 顶点变换，保持原有绘制提交通道 |
| **GPU** | 使用通过自检的 GPU 绘制管线；不可用时回退 Java |

## 启用步骤

1. 打开设置 → 硬件加速。
2. 开启“启用硬件加速”。
3. 选择加速方式。
4. 应用设置。
5. 查看“当前状态”，确认实际模式。

:::note
“当前状态”是只读的，显示实际模式与回退原因；刚修改但尚未应用的偏好不会改变它。
:::

## 状态说明

| 状态 | 含义 |
| --- | --- |
| Java · 已关闭 | 未启用 |
| 检测中 · Java | 正在检测硬件 |
| 已就绪 · 模式 | 加速已生效 |
| Java · 原因 | 加速不可用，已回退 |

常见回退原因：

- 当前平台/架构不支持；
- 未内置匹配的原生库；
- 原生资源完整性校验失败；
- Java 与原生库 ABI 不匹配；
- 原生访问被限制；
- 没有可用的 SIMD 指令集；
- GPU 管线不可用或尚未就绪；
- 光影/渲染模组没有兼容路径；
- 加速资源预算不足。

回退时会在聊天栏提示一次，并继续使用 Java 渲染。

## 与光影的关系

- 部分光影/渲染模组没有兼容的加速路径，会回退 Java；
- GPU 模式需要管线通过自检；
- 开光影后出现画面异常时，先关闭硬件加速对比。

## 性能建议

- 先确认没有回退，再比较帧率；
- 模型/粒子/光源很多时，GPU 模式收益更明显；
- 只使用 SIMD 时，绘制提交仍在 Java 路径；
- 如果出现崩溃或画面异常，关闭加速并提交日志。

## 常见问题

**开启后没有变化？**
查看“当前状态”是否显示“已就绪”；如果显示回退原因，说明实际仍在 Java 路径。

**开启后崩溃？**
关闭硬件加速，记录日志与显卡/驱动信息；不要在不了解原因时反复开启。

**服务器/整合包要求关闭？**
硬件加速是客户端选项，可以随时关闭；不会影响模型文件。
