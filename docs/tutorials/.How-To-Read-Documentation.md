## 基础概念

### 全局对象

全局对象用来存放访问各类信息的函数。例如，与玩家数据相关的函数放在全局对象 <code>player</code> 中，与形象模型相关的函数放在全局对象 <code>models</code> 中。

### 枚举

枚举不是函数，而是函数可能返回或作为参数接收的关键字列表。例如，<code>ParentTypes</code> 枚举包含可以为 modelPart 设置的全部父类型（与 Blockbench 的关键字对应）。另一方面，<code>EntityPoses</code> 枚举包含实体可以呈现的全部实体姿势（包括非玩家姿势），由 <code>getPose()</code> 返回。

## 阅读 Figs

本页将介绍如何借助 Figs 查找并使用 Figura 的全部函数。

我们将以“熟练用户”模式查看 Figs。Figs 默认使用“新手”模式，要切换模式，可以点击网页右上角的 Preferences 按钮。

打开 Figs 后，你首先会看到选择版本的选项，这里指的是你正在使用的 Figura 版本。如果选错版本，可能会缺少某些函数，或者看到实际无法使用的函数。如果跳过版本选择，Figs 会显示 Figura 最新版本中的函数。

无论是否选择了版本，屏幕左侧都会显示一个词条列表。列表顶部是全局对象，向下滚动侧边栏可以看到杂项类型和杂项枚举。

Figs 提供搜索功能，可以匹配函数名称或说明中的任意词。如果不确定某个函数属于哪个全局对象，可以用搜索功能按关键字查找。（例如，想修改相机，就搜索 camera 并向下滚动。）

假设我们要做一个自定义鞘翅，它会根据我们是否穿着鞘翅来开启或关闭。我们本身就是玩家，所以所有信息都在 player API 中。在左侧边栏向下滚动，找到全局对象区域下的 <code>player</code>。除了浏览整个 player API 列表，也可以搜索“item”（因为我们要找物品信息），直到找到 <code>getItem()</code>。

### 如何阅读给出的信息

这里会显示一些信息，每一条都是必要的。你可以点击 <code>PlayerAPI.getItem</code> 打开该函数的完整页面（不过页面上不会提供更多信息）。

<code>PlayerAPI.getItem</code> 告诉我们，<code>getItem</code> 函数属于 PlayerAPI。player API 中的函数通过 <code>player</code> 全局对象访问，因此写成 <code>player:getItem()</code> 即可调用该函数。但这还没有说明如何从中取出想要的全部信息。

继续向下，找到 <code>overload 1:</code>，接下来的这段信息是第二块拼图。

<code>PlayerAPI:getItem(index: Integer): ItemStack</code> 提供了 **四** 条非常重要的信息，前两条我们已经讲过。

第三条信息在括号 <code>()</code> 中，这里是 <code>index: Integer</code>。在这个语境下，“index”指的是要检查的物品槽位。Integer 是整数，所以这表示要检查的槽位由括号中填入的整数决定。

再往上看物品的说明，Figs 会告诉我们 <code>slots are indexed with 1 as the main hand, 2 as the off hand, and 3,4,5,6 as the 4 armor slots from the boots to the helmet</code>。简而言之，作为参数传入的整数决定要搜索哪个槽位。Figs 说 6 是头盔，向下依次到靴子，而我们要的是胸甲槽位，所以要传入的整数是 5。

到这里我们得到 <code>player:getItem(5)</code>，接下来用一小段代码测试它是否生效。

```lua
function events.tick()
    log(player:getItem(5))
end
```

然后……成功了！游戏聊天框被日志刷屏，日志正在告诉我们胸甲槽位里有什么。

消息末尾显示这是一个 ItemStack。回看 Figs 的重载写法：<code>PlayerAPI:getItem(index: Integer): ItemStack</code>，你会注意到 ItemStack 位于括号之后。这是因为冒号 <code>:</code> 后面的信息就是函数的返回值，也就是函数执行完毕后返回给我们的内容。

现在我们可以从胸甲槽位取到信息了，但还没有对这些信息做任何处理，需要进一步查看 ItemStack 提供的信息。

在 Figs 中点击 <code>ItemStack</code>，会打开另一个页面，里面还有更多函数。

我们想知道这个 ItemStack 是否来自鞘翅。最好的办法是查看物品 ID。如果你用过 /give 命令，就会知道给物品时需要填物品 ID，格式类似 <code>minecraft:stick</code>。按 F3+H 打开高级提示框后，也可以在游戏内查看物品 ID。

在 ItemStack 页面搜索 id，就能很容易找到 <code>getID()</code> 函数。

它的重载写法如下：<code>ItemStack:getID(): String</code>

和之前一样，getID() 属于 ItemStack，说明它需要一个 ItemStack 对象。但与 player API 不同，我们没有 ItemStack API，不能直接写 ItemStack:getID()，因为 ItemStack 并不是全局对象（它不在全局对象列表中）。不过 <code>player:getItem(5)</code> 返回一个 ItemStack，可以直接在其上调用 <code>getID()</code>。因此可以写成 <code>player:getItem(5):getID()</code>，用于测试的日志如下：

```lua
function events.tick()
    log(player:getItem(5):getID())
end
```

你可能会想往 getID 的括号里填点什么，那就再回到 Figs 给出的重载写法。<code>ItemStack:getID(): String</code> 中的括号是空的，表示不需要参数，括号里不应填任何内容，填入的内容都会被忽略。

值得注意的是，它返回的是 String，也就是一串字符。给内容加上引号就会变成字符串，因此 <code>true</code> 是布尔值，而 <code>"true"</code> 是字符串。在我们的例子中，这串字符就是胸甲槽位中物品的 ID。现在可以把物品的字符串与鞘翅 ID 的字符串进行比较。

```lua
function events.tick()
    log(player:getItem(5):getID() == "minecraft:elytra")
end
```

这条语句称为求值。双等号 <code>==</code> 会让游戏比较它两侧的两个值；如果两侧是函数，则比较函数返回的值。如果玩家穿着鞘翅，<code>player:getItem(5):getID()</code> 会返回 <code>"minecraft:elytra</code>，与我们检查的值相同，因此游戏会显示 <code>true</code>。求值结果可以与其他代码组合使用，例如存入变量或放进 if 语句中。

至此，我们的鞘翅检测就是 <code>player:getItem(5):getID() == "minecraft:elytra"</code>。它通过 player API 对玩家执行 <code>getItem()</code>，再对玩家的物品执行 <code>getID()</code>，然后把物品 ID 与鞘翅的 ID 比较，判断玩家是否穿着鞘翅。

补充说明：log 也是一个函数，我们把最终结果传给它。它的作用是把作为参数传入的信息输出到聊天框。如果直接照抄日志内容，就会出错。
